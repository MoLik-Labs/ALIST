GETTING STARTED / 01

Quick start

The current production implementation is the native C++20 server. Build it on Linux with a C++20 compiler, Make, SQLite, curl, OpenSSL, and zlib development libraries.

TERMINAL
make -j2 release
./alist server --data ./data --port 5244

Open http://localhost:5244 on the machine running Kova. On first startup, an administrator password is generated and logged. You can set ALIST_ADMIN_PASSWORD before first initialization instead.

Keep your data safe. The data directory contains your database and signing secret. Keep it private, persistent, and backed up.
GETTING STARTED / 02

Configuration

Configuration is stored under the data directory. These environment variables can override startup settings:

VARIABLEPURPOSE
ALIST_DATA_DIRData directory; CLI --data takes precedence.
ALIST_HTTP_PORTHTTP port; defaults to 5244. CLI --port takes precedence.
ALIST_ADMIN_PASSWORDInitial administrator password, only when creating the first account.
ALIST_SITE_URLPublic origin used when absolute links are needed.
ALIST_TRUST_PROXYTrust forwarded headers only behind a trusted, non-bypassable proxy.

See the repository README for the complete configuration and environment reference.

DEPLOYMENT / 01

Docker & hosting

Use the included Compose configuration to build and start the native server:

TERMINAL
docker compose up -d --build

Compose persists data in ./data. Other container hosts should persist /opt/alist/data and ensure it is writable by the container user. Standard Heroku dyno filesystems are ephemeral and are not suitable for durable data.

DEPLOYMENT / 02

Cloudflare, considered.

The included Worker is an optional reverse proxy—not a standalone Kova server. It requires a separately hosted HTTPS origin with persistent storage. Streaming requests and responses pass through the Worker; Cloudflare platform limits still apply.

Trust is a boundary. Restrict direct access to your origin before trusting forwarded headers. Keep ALIST_TRUST_PROXY disabled if clients can bypass the trusted proxy.

See the Worker deployment guide ↗ for setup and operational details.

DEPLOYMENT / 03

Security checklist

  • Use HTTPS through a trusted reverse proxy.
  • Use a strong administrator password and enable two-factor authentication.
  • Protect and back up the database and signing secret together.
  • Keep proxy trust disabled unless the origin cannot be bypassed.
  • Review storage permissions and keep private-network access disabled unless needed.
REFERENCE / 01

One workspace, many sources.

Kova brings file browsing, search, sharing, previews, uploads, WebDAV, and administration together. The native server includes local, S3, WebDAV, Google Drive, OneDrive, Dropbox, SFTP, FTP and virtual storage drivers. Availability and behavior depend on each backend’s configuration.

REFERENCE / 02

The Go migration

A Go implementation is under development. Its experimental server exposes liveness and an optional separate local workspace with opt-in uploads; it is not a replacement for the native release. Database compatibility, drivers, API, WebDAV, authentication and upgrade paths must be implemented and tested before a production cutover.

Performance claims require measurements on representative workloads; changing language alone is not a guarantee.

REFERENCE / 03

Build with confidence.

Run the native test suite and browser UI checks before submitting changes. Go packages can be tested independently as they are ported.

TERMINAL
make -j2 test
npm ci
npm run test:webui
npm run test:worker
go test -race ./...
